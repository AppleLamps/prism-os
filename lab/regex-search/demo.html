How the pattern fits the program
States
A pattern needs one state for each character or set in the pattern, plus one.
Character classes
Characters that no part of the pattern tells apart share a class, e.g. b, c and d in a|[a-d].
Class boundaries
The places along the character codes where the class changes, e.g. before a and after z for [a-z].

What a pattern can use

a é 7That character. A character with a meaning of its own needs a backslash, e.g. \. or \(.
.Any character except a line break.
[a-z_] [^0-9]One character of the set, or with ^, one character outside the set.
\dA digit, 0 to 9.
\wA letter from a to z or A to Z, a digit or an underscore.
x? x* x+At most one x, any number of them, and at least one.
the|anOne side or the other.
(ab)+A group, here repeated.

Not in this language: anchors such as ^, counted repeats such as {2}, lazy repeats such as *?, and other escapes such as \s.

What the search finds

The search takes the longest match from the leftmost start, and never an empty one, which differs from JavaScript’s RegExp: e.g. a|ab finds ab in cab here, and a in JavaScript.

Limits

The program has a fixed size. It holds a fixed number of states, and a pattern needs one state for each character or set in it, plus one, e.g. 8 for (the|an?) [a-z]+. A larger pattern gets a sentence instead of matches, e.g. “This pattern needs 13 states, and the program holds 12.” The program also reads a fixed number of characters, and text past that capacity is gray and isn’t searched.

The one program for every pattern grows with the square of the number of states: 12 states and 768 characters are about 310,000 operations, and 32 states and 1,024 characters would be 2.3 million, which take seconds to build and more than a gigabyte of memory. So the page builds no program of more than 1 million operations. A program built for one pattern is much smaller, e.g. about 40,000 operations for the starting pattern, and every change of the pattern builds a new one.
