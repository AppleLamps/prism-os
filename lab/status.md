## Runtime additions since September 14, 2026

On September 14, Cheng chose the recommended option for three runtime questions ([decisions 1 to 3](ui-exploration/guide/review-and-decisions.md#decisions-for-you)). Every existing circuit compiled to the same program with the same values, e.g. IndirectOS stayed at 5,253 operations in 192 layers until the changes below.

- **Index reads.** `circuit.indexRead` and `circuit.indexReadAffine` copy `candidates[floor(index)]` in 1 operation at any table size, for an index range strictly inside ±2^24. A gradient into the index throws unless the caller passes `'zero'` or `'backward-difference'`. The `recomputeDepths` option recomputes layers after gather lowering, and is off by default ([index reads](../docs/execution-model.md#index-reads), [compilation](../docs/execution-model.md#compilation)).
- **Comparisons.** `emitCompare` builds an exact bit of `>`, `>=`, `<`, `<=` or `===` from declared ranges: integer bits when both operands lie on grids declared with `assumeGrid`, e.g. 2 operations in 2 layers for `a >= b` on a 1/64 grid, and a sign cascade otherwise, e.g. 15 operations in 14 layers for `a >= b` within 0..16,384. `emitMinimumExact`, `emitMaximumExact` and `emitClampExact` select one operand with such a bit, and `emitFirstActive` counts these bits and index reads of bits as proven bits ([comparisons](../docs/execution-model.md#comparisons), [grids](../docs/execution-model.md#grids)).
- **Rounding points.** The builder records boolean atoms, `emitCompare`'s operations, and operations marked with `markRoundingPoint`, so a backend may reorder or fuse every other sum ([rounding points](../docs/execution-model.md#rounding-points)).
- **Springs and time.** host-timing.ts counts 4 ms spring steps and writes a 4-number step matrix per stiffness and damping pair, which `emitApplySpringMatrix` and `emitAnimatedObject` apply. `advanceFrame` steps springs to each event's timestamp before applying the event, snaps objects onto their destinations past 300 steps in one frame, and with `'events and settle checks'` writes state back only at events, settle checks and snaps ([springs and time](../docs/execution-model.md#springs-and-time)).

On September 15, 2026, IndirectOS and its Photos app moved to these additions. Windows and thumbnails are `emitAnimatedObject`s that share one spring matrix, the machine runs `advanceFrame` with `'events and settle checks'`, every destination change reaches the machine as a timestamped event, including viewport resizes, and Photos lays out at the window's destination size. The machine reads a click's viewport coordinates relative to Photos' content box at the window's destination, so during a maximize, `photoClick` selects the photo that ends up under the pointer, though until September 16 the page didn't deliver every such click (see below). Each window's content box takes the destination size at the event, while only the frame animates and clips the content, so Notes' text reflows once per event instead of at every in-between size. The window hit tests compare each edge distance with `emitCompare`, with pointer coordinates rounded to 1/64 px and window geometry declared on a 1/64 px grid, so each comparison is an integer bit, and they decided like the previous form on every press tested ([comparisons](../docs/execution-model.md#comparisons)). `emitFrontmost` stays, since at 4 windows its chain is smaller than an `emitFirstActive` tree. IndirectOS went from 5,253 to 3,654 live operations and from 192 to 124 layers, and standalone Photos from 2,358 to 1,759 operations and from 91 to 67 layers. In window-manager.test.ts's timestamped session, committed tables and drawn outputs at shared times are identical in every bit at 10, 30, 60 and 120 fps and through 500 ms stalls, where the pre-change IndirectOS in lab/ui-exploration/codegen differs from 120 fps by up to 357 px at 10 fps and 71 px at 60 fps.

On September 16, 2026, the Notes flow from [lab/ui-exploration/indirect-os-2](https://github.com/chenglou/indirect/tree/exploration-2026-09/lab/ui-exploration/indirect-os-2) moved into root IndirectOS, in notes.ts, notes-walker.ts and notes-paragraph.ts. Arrow keys and Escape reach Photos only while Photos is the focused window. IndirectOS went from 241 to 438 source cells, from 3,654 to 14,019 live operations, from 124 to 275 layers, from 7,890 to 31,359 stored weights, from 12 to 908 gather reads, and one evaluation from about 25 µs to about 81 µs. ## Known issues in production code

- IndirectOS runs one evaluation per distinct event timestamp, and validates the table and the root values in JavaScript at each one. E.g. a 60 fps frame of a title bar drag with 4 pointer moves runs 5 evaluations in about 445 µs, where one evaluation of the program alone takes about 81 µs. Since September 16, 2026, while nothing animates and no press is held, a frame whose events are all pointer moves runs only the last move, e.g. a hover frame with 4 moves runs 2 evaluations, the move and the frame, in about 183 µs, where running every move takes 5 evaluations. Moves during a drag, a resize or an animation each still run. The lab measured checks like these as small next to one evaluation: on September 13, 2026, [indirect-os-2](https://github.com/chenglou/indirect/tree/exploration-2026-09/lab/ui-exploration/indirect-os-2) measured a validator derived from the cell declarations at 0.75 µs for 759 cells, and in July 2026, [gather-lowering](https://github.com/chenglou/indirect/tree/exploration-2026-09/lab/gather-lowering) measured a check of every declared one-hot group at 0.2 to 0.7 µs for groups of 64 to 256 members, and about 4 µs at 4,096 members. Like [decision 4](ui-exploration/guide/review-and-decisions.md#4-what-should-agents-build-apps-from)'s first follow-up, gather-lowering and [index-read](https://github.com/chenglou/indirect/tree/exploration-2026-09/lab/ui-exploration/index-read) proposed checking stored cells when they're written back, instead of at every evaluation. [input](ui-exploration/input/README.md#rough-cpu-time-per-frame)'s window circuit ran a frame of about 5 events in 12.6 µs as one evaluation over a queue, against 16.9 µs with one evaluation per event.
- The title bar buttons are laid out twice: by the program's arithmetic for hit tests, e.g. the close button's left edge is `left + width - buttonGap - buttonSize` (window-manager.ts:478-483), and by CSS flexbox for drawing, inside the window's 1 px border (window-manager.css:98, 114 and 145-149). So each drawn button sits 1 px left of and 1 px below its hit rectangle. The hit rectangle extends half the button gap past the button on every side, which hides the 1 px offset. These sizes, e.g. the title bar height and the button gap, are also written three times: in the source table, as CSS custom property defaults (window-manager.css:24-29), and in a JavaScript copy at mount (window-manager.ts:1601-1609). lab/ui-exploration's [note on IndirectOS](https://github.com/chenglou/indirect/blob/exploration-2026-09/lab/ui-exploration/notes/indirect-os.md), section 2, found both before September 15, 2026, and both still hold.
- Range propagation doesn't track NaN: a ReLU of a wire with an open range gets the range 0..Infinity, and a later product can get a finite range while holding NaN. So when a source cell holds Infinity, gather lowering can skip an unselected product whose dense sum is NaN. `bun lab/ui-exploration/codegen/nan-range-case.ts` finds 10 source tables over 200 random circuits where the executor and the reference evaluator differ on today's numeric-ui-core.ts. The demos can't reach the case, since their JavaScript validation rejects non-finite sources ([codegen](ui-exploration/codegen/README.md)).
- Not production code, but agents copy it: most guide examples still use the older defaults, e.g. the toggle switch in [guide/sections/model.md](ui-exploration/guide/sections/model.md) uses rounding stages and `emitSpring`, which `emitCompare`, `emitAnimatedObject` and `advanceFrame` replaced as defaults on September 14.

## Reusable layout

Run `bun run start:reusable`. The demo compares ordinary wrapping, search for each layout, and the shared learned rule. Controls change viewport width, collection, item count, and captions. All methods keep reading order and required content; scrolling is allowed.

Under the authored preference objective, the shared rule transfers well to new counts and widths and leaves a visible gap with longer captions and unfamiliar crops; the loss table is in the experiment's [results](reusable-layout/README.md#results). This is learned responsive sizing within a fixed flow layout, not generation of arbitrary page structures. The wrapping baseline uses a fixed preferred width; we have not shown that the model beats a carefully tuned responsive formula or measured how much it improves on a width-only model. Every method has zero measured missing items, text overflow, horizontal overflow, and overlap in those sets. Resize sweeps still find abrupt reflow. The photo corpus is shared between training and evaluation; different crops are not new photographs.

## Correctness changes

- Whole multiplication and selection retain their meaning for differentiation while expanding to the existing forward atoms. Multiplication at zero now has the intended derivative in either operand order. Boolean surrogate gradients require an explicit option.
- Selection uses two masked products, avoiding overflow from subtracting large finite candidates.
- `roundAffine` preserves evaluation boundaries, constant and duplicate terms, and term order through inlining. Ordinary `affine` remains a simplifiable builder expression.
- Numeric bounds follow rounded FP32 operations and account for overflow. Min/max no longer claim ideal mathematical bounds where their arithmetic can drift. Their preserved rounding and weaker bounds cost some additional layers and live operations.
- The trace compiler propagates returns, rejects mutations in runtime conditional expressions it cannot safely handle, and compares nullable values correctly. Its source interpreter is independently checked against native JavaScript; intentional FP32 drift is reported separately.
- Real-source compiler tests use a verified historical source fixture. Compatibility with the latest external file is an optional `--live` check, not an assumption that another repository remains unchanged.
- Layout fitness includes direct parameter derivatives. The event demo retains queued and browser-coalesced pointer moves, including outward-and-back movement that cancels a click.

See [execution semantics](../docs/execution-model.md), [macro contracts](../docs/execution-model.md#macro-contracts), and the regression tests for exact domains. This is not a proof of all possible circuits or all JavaScript programs.

Gather lowering recognizes 26 candidate-gallery reads and 908 window-manager reads, where the window manager had 12 before the Notes flow moved into it on September 16, 2026. Candidate-index tables and candidate computation remain. The pass optimizes retrieval after selection; it does not discover query/key scoring.

`createTensorEvaluator(roots)` reuses execution buffers and returns only requested outputs ([buffer lifetime](../docs/execution-model.md#buffer-lifetime)). [Runtime measurements](runtime-cost/README.md) compare it with the evaluators that return full arrays, on the CPU.

## Still open

The next interpreter question is whether fractional training examples identify the required addition grouping. Scaling to longer programs without a complete loss table, learning a search guide across task families, and discovering shared query/key functions remain untested. The data-adapter baseline supplies a small exact task and independent oracle for that next comparison.

For UI, the next evidence should come from broader content and an explicit human task, not from interpreting synthetic preference scores as usability. GPU execution, a general JavaScript compiler, learned arbitrary abstractions, and a full learned UI runtime are not delivered by these experiments.
