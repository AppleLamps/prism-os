      How it works
      

        
The page writes its documents itself: package manifests, user records, log events and four more shapes, each up to 512 characters, and 1 in 10 broken on purpose, e.g. by a missing quote. Each character goes to the GPU once, as a number.

        
The JSON highlighter is one small step, built by hand from weighted sums, ReLU gates and table reads. It runs at each of a document’s 512 positions and says what each character is, e.g. part of a key or of a string value, and where the first error is.

        
Regex search is a second such step. A keystroke turns the pattern into tables of numbers, and the step runs over each document’s positions, backward and then forward, and counts the matches. A new pattern changes the tables, never the program.

        
The search reads the highlighter’s answer for each character from the GPU’s memory, which is how it can read only string values or only keys.

        
No document reads another document’s numbers, so the GPU runs every document at the same time. JavaScript gets back one match count per document and paints the map, and for the document on screen, a mark per character.
