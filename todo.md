## Revisit hardAttend (dynamic lookup as an atom)

The June 3 plan had a third atom next to affine and reglu: hardAttend, which scores a set of candidates against a query and returns the values of the single highest-scoring candidate — attention with an exact winner instead of a weighted blend. It was dropped because expressivity didn't need it: the parallel-winner tree (parallel-winner.md) selects a winner with affine and reglu alone. Since then, several macros do the same job and each pays work proportional to the collection size on every read: one-hot indexing multiplies all N items by a 0/1 mask and sums, bounded visibility compaction routes the K visible items out of N, and the learned-wiring experiment picks each gate input with a soft mixture over every candidate wire.

Revisit when a real UI reads from a large collection at an index computed at runtime. For example, a photo library with a thousand photos where the lightbox shows one: one-hot indexing costs a thousand multiplies per geometry read; a lookup atom costs one lookup. If adopted, the atom must meet the same requirements as the existing atoms: an exact FP32 result with a declared tie rule (the June 3 notes: "hardmax must have one winner, or a specified tie rule"), and a soft training form (softmax over the scores) that hardens to the exact winner, the same way relation cells and wiring selections already train soft and run exact. Percepta's transformer-vm is the working precedent: lookup gates plus gated ReLU gates, with convex-hull queries over 2D keys making the lookup logarithmic at execution time.

On differentiability: hardAttend is exactly as differentiable as the current one-hot selection, no better and no worse. In both designs, gradients flow through the retrieved values; the winner choice itself is the non-differentiable step (today it is the boolean atoms inside emitArgmax's pairwise comparisons); and softmax over the scores is the shared soft training form. The learned-wiring experiment already trains this way — a soft mixture over candidate wires, sharpened, then hardened to the argmax candidate — which is soft attention hardening into a lookup, just without the name.
